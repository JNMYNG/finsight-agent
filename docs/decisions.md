# Day 1 설계 선택과 검증 기록

작성일: 2026-10-19 (KST)

## 1. 구현 범위와 계층

`src/finsight` 패키지에 설정·도메인 모델·OpenDART 통신·기업목록·순수 계산·서비스·CLI를 분리했다.
기존 [FinAgent](https://github.com/JNMYNG/FinAgent)의 README, `app/agent.py`, `app/tools.py`를
확인하고 Python 계산을 Agent에서 분리하는 책임 구분을 이어갔다. 기존 코드를 그대로 복사하지 않았다.
금융 원천 데이터 계층을 먼저 검증하기 위해 LangGraph, RAG, OpenAI, 웹 UI는 추가하지 않았다.
ChromaDB, FastAPI, Streamlit, Docker와 해당 의존성도 후속 단계에서 도입한다.

실행 의존성은 httpx, python-dotenv, defusedxml이다. 테스트/검사는 pytest, pytest-cov, Ruff를 사용한다.
`pyproject.toml`은 허용 범위를, `uv.lock`은 구체적인 버전과 해시를 관리한다.
검증 환경은 Python 3.11이다.

## 2. 공식 API 계약 확인

| API | 요청 | 성공 응답 | 구현의 처리 |
| --- | --- | --- | --- |
| [고유번호](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018) | `crtfc_key` | ZIP 안 XML 기업목록 | 메모리에서 CORPCODE.xml 읽기, XML 오류 응답도 별도 처리 |

`corp_code`가 응답에 추가로 존재한다면 함께 대조한다. 접수번호도 검증한다.

## 3. 재무제표와 기간 선택

자동 선택은 응답 전체에 CFS가 있으면 연결을 사용하고, CFS가 전혀 없을 때만 OFS로 전환한다.
전환은 `FALLBACK_TO_OFS`로 명시한다. 연결의 특정 계정이 없다는 이유로 별도 값을 섞지 않는다.
호출자가 CFS 또는 OFS를 명시하면 다른 구분으로 전환하지 않는다.

연간은 `thstrm_amount`, 분·반기는 `thstrm_add_amount`를 세 항목 모두에 일관되게 사용한다.
누적금액이 없으면 결측으로 남긴다. 출력에 `period_basis`와 선택한 금액 필드 및 원본 당기일자를
기록한다. 다른 결산월·회계기간의 비교는 기간 근거가 맞을 때만 허용한다. 원본 날짜의 표기 차이는
정규화하지만 원본 문자열도 보존한다. 분·반기의 원본 당기일자는 API의 표기 그대로이며,
누적 시작일을 임의 생성하지 않는다.

## 4. 항목 추출과 결측

계정명은 유니코드/공백/선행 번호를 정규화한 뒤 명시적인 별칭으로만 매칭한다.
부분 문자열 검색은 지배주주 귀속 순이익 등 다른 의미의 계정을 선택할 수 있어 사용하지 않았다.
공식 주요계정은 IS를 제공하며, 응답 변화에 대비해 CIS도 손익 항목으로 허용한다.

중복은 값·통화·날짜·접수번호가 모두 일치할 때만 인정한다. 합산하지 않고 근거는 모두 남긴다.
충돌은 `AMBIGUOUS_ACCOUNT`로 표시하고 계산에서 제외한다. 잘못된 금액 형식, 통화 누락,
기간 누락도 값의 사용을 중단한다. 결측과 실제 0은 구분하며, 외부 데이터나 LLM으로 보정하지 않는다.

영업손실 같은 계정명에서 금액 부호를 추정하지 않는다. API의 부호를 사용한다.
원본 계정명·금액 문자열·금액 필드·통화·당기명/일자·접수번호, 기업 문맥·API URL·조회시각을 보존한다.

## 5. 계산과 비교

모든 금액·비율은 Decimal로 계산한다. 영업이익률은 `영업이익 / 매출액 × 100`,
소수 둘째 자리, ROUND_HALF_UP이다. 0 이하 매출액은 비율을 해석하지 않고 사유와 null을 반환한다.
음수 영업이익은 그대로 허용한다. 매출액과 영업이익의 통화·기간·접수번호가 다르면 비율을 만들지 않는다.

비교 결과는 두 기업의 값과 `왼쪽 - 오른쪽` 차이를 제공한다. 보고서·구분·기간·통화 불일치는 차이 계산을
중단한다. 이익률 차이는 %p다. JSON의 Decimal은 문자열, 결측은 null로 출력한다.
임의의 환율 환산·억원 환산·매출액 비율 비교·우열에 대한 자연어 평가는 추가하지 않았다.

## 6. 키와 실패 처리

환경변수는 명시적으로 로딩한다. `OPENDART_API_KEY`를 기본으로 사용하고 기존 `.env`의
`DART_API_KEY`를 대체 이름으로 지원한다. 두 이름이 모두 있으면 전자를 우선한다.
기존 `.env`는 수정하지 않았다. `.env.*`도 제외하되 `.env.example`만 추적한다.

API 상태 오류, HTTP 오류, 타임아웃, JSON/XML/ZIP 손상을 구분한다. 013은 NoDataError다.
httpx 오류 문자열에는 인증키가 포함된 URL이 있을 수 있어 공개 예외와 traceback에서 원래 통신
예외를 제거한다. API 메시지가 키를 되돌려주면 마스킹한다. 응답 데이터의 출처 URL에는 키가 없다.
ZIP은 파일시스템에 풀지 않고 XML 크기를 제한하며, defusedxml로 엔티티 확장 등을 거부한다.
Day 1에는 키가 포함될 수 있는 HTTP 상세 로그 설정을 추가하지 않았다.

## 7. 실제 발생한 오류와 수정

### 기업목록의 영숫자 종목코드 거부

최초 실제 비교 실행에서 기업목록 다운로드는 성공했지만 `잘못되거나 중복된 기업 정보` 오류로
조회가 중단됐다. 원인은 종목코드를 6자리 숫자로만 가정한 검증이었다.
다운로드한 119,664개 항목 중 64개에 `0068Y0`, `0015S0` 등 영문자를 포함한 종목코드가 있었다.
이는 공식 가이드의 6자리 문자열 설명을 숫자로 과도하게 제한한 구현 오류였다.

종목코드를 6자리 영숫자로 허용하고 대소문자 입력을 정규화하도록 수정했다. 기업 고유번호의
8자리 숫자 검증은 유지했다. 합성 기업목록에 영숫자 코드를 넣은 회귀 테스트를 추가했다.

### 개발 환경의 캐시·네트워크 제한

최초 `uv lock`/`uv sync`는 사용자 캐시 디렉터리 접근 제한으로 실패했다. 승인된 실행으로 의존성을
설치했다. 최초 GitHub와 OpenDART 요청은 샌드박스 DNS/네트워크 제한으로 실패했고,
승인된 네트워크 실행으로 다시 확인했다. OpenDART 통신 실패가 오류 JSON/종료 코드 1로
보고되는 것도 실제 실행에서 확인했다.

### 스타일 검사

최초 Ruff 검사에서 한국어 예외 메시지 3곳의 줄 길이 위반이 발견되어 줄바꿈을 수정했다.

# Day 2 — LangGraph Agent

작성일: 2026-10-19 (KST). Day 1 기록은 당시 구현·검증 범위를 보존한 것이다.

## 10. 기존 코드 분석과 재사용

작업 전 저장소는 변경 사항이 없는 상태였고, 기존 pytest 143개를 직접 실행해 통과를 확인했다.
`CorporationDirectory.find`, `FinancialService.get_financials`, `compare_summaries`,
`calculate_operating_margin` 및 불변 근거 모델이 그대로 재사용 가능했다.
재무 추출·계산·비교 알고리즘과 Day 1 테스트 본문은 변경하지 않았다.

직렬화 함수만 `cli.py`에서 `serialization.py`로 이동하여 CLI·Tool·로그에서 공유한다.
기존 CLI에서도 같은 함수 이름을 사용할 수 있다. 환경 설정에 별도 `AgentSettings`를 추가해
OpenAI 키가 없어도 기존 Day 1 명령은 실행되도록 했다. 테스트 공통 설정에는 환경 격리와
Agent용 HTTP Mock fixture를 추가했다.

## 11. Agent 실행 구조

LangGraph StateGraph에 `model`, `tools`, `report` 노드를 정의했다.
모델이 Tool을 선택하면 순차 실행한 관측 결과를 다시 모델에 전달하고, 완료 시 보고서를 렌더링한다.
실행마다 State와 재무 요약 캐시를 새로 만들어 질문 간 수치가 섞이지 않도록 했다.
같은 실행에서 재무 조회 후 지표 계산을 요청하면 같은 기업·연도·보고서·구분의 조회를 재사용한다.

OpenAI 공식 SDK는 `model.py`에 격리했다. 모델 인터페이스를 주입할 수 있어 자동화 테스트는
실제 LangGraph와 ScriptedModel을 사용한다. 실제 모델은 기본 `gpt-4.1-mini`로 검증했다.
모델 변경은 `OPENAI_MODEL`로 명시하며 자동 대체는 하지 않는다. 타임아웃 30초, SDK 자동 재시도는
0회다. OpenAI에 요청 결과 저장을 요청하지 않도록 `store=False`를 전달한다.

OpenAI Docs 스킬로 [공식 Function calling](https://developers.openai.com/api/docs/guides/function-calling)과
[모델 기능](https://developers.openai.com/api/docs/models/gpt-4.1-mini)을 확인했다.
strict 함수 스키마, 모든 인자의 명시적 전달, 추가 속성 거부, 병렬 호출 비활성화를 적용했다.
그래프 구성은 [LangGraph 공식 문서](https://docs.langchain.com/oss/python/langgraph/workflows-agents)를 참고했다.

## 12. Tool과 수치 생성 차단

기업 조회, 재무제표 조회, 영업이익률 계산, 기업 비교를 각각 함수 Tool로 연결했다.
추가 조건이 필요한 경우를 위해 필드 목록만 받는 `request_clarification` Tool도 제공한다.
모델에서 매출액·영업이익 같은 원시 금액이나 계산식을 받는 Tool은 제공하지 않았다.
`calculate_metrics`는 Day 1 서비스가 실제 재무제표로 계산한 영업이익률을 반환한다.

Tool 입력은 strict Pydantic 모델로 검증하고, 질문에 명시된 연도·구분·보고서와 다른 인자는
조회 전에 거부한다. 사업연도가 없는 질문에서 모델이 연도를 만들어도 재무 조회를 실행하지 않는다.
상대 연도는 한국 시간의 현재연도 기준이며, 명시적인 연도 범위도 지원한다.

최종 보고서는 자유 형식 모델 응답을 사용하지 않는다. Python이 성공한 Tool 결과와 구조화된
오류에서만 금액·비율·기업·기간·구분·출처를 렌더링한다. 모델의 숫자 생성 금지 프롬프트만으로
정확성을 보장할 수 없다고 판단했기 때문이다. 이익률 우열 문장도 Python 계산 결과로 만든다.
자동화 테스트에서 모델이 가짜 수치를 출력해도 최종 답변에 포함되지 않는 것을 확인했다.

## 13. 오류, 로그, 종료 상태

기업 없음/동명이인, API 데이터 없음, API 상태 오류, 통신 오류, 잘못된 응답, 잘못된 Tool 입력은
구조화된 관측 결과로 반환한다. 결측 수치를 생성하지 않는다. 모델 오류가 발생해도 이미 완료한
조회 결과는 유지하며, Tool/모델 호출 상한은 각각 기본 8/10회다. 실패 호출도 상한에 포함한다.

`completed`, `partial`, `error`, `needs_input`, `limit_reached`로 결과를 구분한다.
결측·경고가 있는 성공 조회도 partial로 구분한다. CLI는 completed/needs_input에 0,
partial/error/limit_reached에 1을 반환한다.

로컬 `logs/agent.jsonl`에 실행 ID, 이벤트 시각, Tool 순서·호출 ID·검증된 인자·결과·소요시간을 기록한다.
동일 정보를 결과 JSON의 tool_calls에서도 확인할 수 있다. 모델 자유 응답, 헤더, API 인증키를
로그에 넣지 않으며 알려진 키·인증 필드·키 형식을 마스킹한다. 로그 디렉터리는 Git에서 제외했다.

## 14. 실제 발생한 오류와 수정

### OpenAI strict Tool 스키마 거부 (HTTP 400)

최초 실제 Agent 실행은 Tool을 호출하기 전에 `invalid_function_parameters`로 실패했다.
키를 노출하지 않는 오류 유형과 스키마 진단을 기록하도록 개선한 뒤 원인을 확인했다.
Pydantic이 enum 필드를 `$ref`와 그 옆의 `description`으로 생성했는데 OpenAI가 이를 거부했다.
문제 위치는 get_financials의 report_type 필드였다.

OpenAI에 전송하는 스키마에서 로컬 enum 참조를 펼치도록 수정했다. 서버의 strict 입력 검증은
그대로 유지하고, 전송 스키마에 $ref가 남지 않으면서 보고서 enum 값이 보존되는 회귀 검증을 추가했다.
수정 후 실제 모델의 두 연도 비교와 세 단계 순차 Tool 호출이 모두 성공했다.

### 오류 원인을 구분할 수 없던 model_error

첫 실패 결과는 model_error만 반환하여 인증·한도·스키마 오류를 구별할 수 없었다.
HTTP 상태와 허용된 오류 코드, 키를 제거한 스키마 진단을 error 필드 및 로그에 추가했다.
SDK 예외의 원문 traceback은 유지하지 않는다. API 오류 본문에 키가 있어도 노출되지 않는 테스트를 추가했다.

### 테스트 fixture import와 Ruff F811

초기 Agent 테스트에서 다른 테스트 모듈의 fixture를 직접 import하자 Ruff가 테스트 인자와의
이름 충돌을 보고했다. 공용 fixture를 conftest.py로 이동해 해결했다.

## 21. Embeddings와 Chroma, 중복/재색인

OpenAI Docs 스킬을 사용해 [Embeddings 규격](https://developers.openai.com/api/docs/guides/embeddings)을
확인했고, text-embedding-3-small 1536차원과 명시적인 24개 배치를 사용했다. 입력의 UTF-8 바이트를
8000 이하로 제한한다. Chroma 기본 임베딩 함수를 사용하지 않아 별도 모델 다운로드가 없다.

[Chroma 메타데이터 필터](https://docs.trychroma.com/docs/querying-collections/metadata-filtering)를
사용해 기업·사업연도·보고서·접수번호·활성 세대·문단 종류를 제한한 뒤 코사인 유사도를 계산한다.
동일 내용/파서/위치의 조각 ID는 결정적이며 동일 세대 조각을 재임베딩하지 않는다.
모든 배치 저장이 끝난 후에만 SQLite manifest에서 활성 세대를 갱신한다. 실패한 재색인은
이전 세대를 유지하고 이미 저장된 새 배치를 재사용할 수 있다.

다른 세대의 벡터는 로컬에 보존한다. 검색에는 활성 세대만 포함하며, 전체 DB 레코드 수와 활성
조각 수는 다를 수 있다. 이번에는 표 위치 수정을 반영해 파서를 v2로 올리고 세대를 갱신했다.
반복 실행으로 같은 세대의 조각 수가 계속 늘어나지 않는 것을 테스트했다.

## 22. 문서 근거의 신뢰 경계

search_disclosures는 검증된 기업·연도·보고서와 검색어만 받는다. 설명 근거는 실제 검색 문장에서
발췌하고, 모델 자유 응답의 숫자나 원인 서술을 사용하지 않는다. 표시되는 재무 수치는 기존 Python
계산값이다. 인용의 수치 표현은 생략하고 원본 문자열은 Tool 증거에 남긴다.

문서 본문과 제목을 Tool 선택 모델에 전달하지 않는다. 모델은 신뢰된 기업 식별자·결과 수·조각 ID·
검색 상태만 관측한다. 실제 본문은 Python 보고서에서 데이터로 렌더링하며 지시문을 실행하지 않는다.
문서 지시문과 가짜 수치가 모델 입력으로 전달되지 않는 회귀 테스트를 추가했다.

결과가 없거나 관련성이 부족하면 NOT_INDEXED/INSUFFICIENT_EVIDENCE와 근거 부족 안내를 반환한다.
두 기업 중 하나의 검색을 생략하거나 요청한 재무 계산 없이 서술만 검색했다면 완료로 표시하지 않는다.
각 근거에 기업·2024년·사업보고서·접수번호·출처 링크·제목 경로·XML 위치를 제공한다.

## 23. 실제 발견한 오류와 수정

- 중단 시 남은 Ruff E501 3개: 문자열 줄바꿈으로 수정했고 최종 lint/format 모두 통과했다.
- 표의 긴 한 행을 여러 조각으로 나눌 때 끝 행이 0으로 기록될 수 있었다. 마지막 실제 버퍼 행을
  추적하도록 고치고 같은 원문 행 번호를 유지하는 회귀 테스트와 파서 v2를 적용했다.
- 실제 검색에 2025년 전망과 과거 연도 회고 문장이 섞였다. 문장별 연도 맥락·전망/계획 표현을 검사하고,
  연도가 불분명한 현재형 서술도 보수적으로 제외했다. 미래 전망을 2024년 실적 원인으로 쓰지 않는다.
- 최초 실제 Agent는 "실적 차이"라는 짧은 검색어를 전달해 근거 부족으로 종료했다. 검색어에 기업·연도·
  보고서 문맥을 넣고 짧은 일반 실적 질문에는 고정 주제 검색어를 보완한다. 적용 검색어는 별도 기록한다.
- 다음 실행에서는 P 태그의 짧은 소제목이 설명 근거로 선택됐다. 소제목을 충분한 설명으로 인정하지 않고
  서술 문장 기준을 추가했다. 제한된 두 문서에서 후보 풀을 100개로 늘린 뒤 기준을 통과한 문장을 선택한다.
- 위 실패들을 최종 성공으로 간주하지 않았다. 수정 후 실제 원문 대조 및 예시 Agent 실행을 다시 수행했다.
